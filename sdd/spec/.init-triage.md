# Init Triage

Items raised during `/sdd init` Import Mode that need user decisions before the spec can be considered complete. Each item is resolved interactively via `/sdd init` Resume Mode.

While any `**Status:** open` items remain, `sdd/spec/config.yml` carries `transition: true` and PR-boundary review enforcement is suspended for the transition.

## TRIAGE-001: Legacy login surface appears unreferenced

**Status:** resolved-corrected (2026-06-01)

**Target REQ:** REQ-SESS-001 / REQ-BOOT-002

**Context:** `lib/main.dart` imports `lib/screens/simple_login_screen.dart` and routes unauthenticated users to `SimpleLoginScreen`. `lib/screens/login_screen.dart` defines a separate `LoginScreen`, but current-source grep finds no inbound reference from startup, home, or settings navigation. Prior closed PR context also treated this file as legacy, but that PR did not merge.

**Recommendation:** Confirm whether `lib/screens/login_screen.dart` is dead code. If yes, archive or delete it in a dedicated cleanup change; if no, wire it into navigation and update the Server Session requirements.

**Resolution:** Corrected by user as a future feature, not dead code and not current product behavior. Current requirements remain anchored to `SimpleLoginScreen`; the alternate login surface stays outside implemented scope until a future planned requirement wires it into navigation.

## TRIAGE-003: File protection action is best-effort

**Status:** resolved-accepted (2026-06-01)

**Target REQ:** REQ-REMOTE-002

**Context:** `lib/services/file_upload_service.dart` method `setFilePassword` tries multiple endpoints and returns `false` after failures. `lib/screens/home_screen.dart` exposes a protection action, but the failure path does not clearly tell the user that the remote item stayed unchanged.

**Recommendation:** Confirm whether file protection is supported by the target server. If supported, document the supported endpoint and surface failures to the user; if unsupported, remove or hide the file protection affordance.

**Resolution:** Accepted as best-effort current behavior. The official requirement remains scoped to an attempted remote protection update, with guaranteed remote protection support excluded until upstream support is confirmed.
